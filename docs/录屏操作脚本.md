## 第五段｜诊断与改进（约 150 秒）

**操作**：
```bash
.venv/bin/python -c "
import csv
from collections import Counter
rows=list(csv.DictReader(open('out/week1_optimize_v0.csv',encoding='utf-8-sig')))
bad=[r for r in rows if r['人工判分'] in ('错','部分对')]
print('失败条数:', len(bad), '/', len(rows))
for k,v in Counter(r['失败原因'] for r in bad).most_common():
    print('  ', k, v)
"
```

**口述**：

> 「按失败原因归类。最大的一类是『检索没命中』，占 92%。
> 说明问题不在模型——两个模型正确率完全一样，一个云端大模型、一个本地 4B，
> 都是 56%。瓶颈在检索：命中的段落不是答案所在的段落。」

**操作**：打开 `week1.py` 的 `Retriever` 类（约第 70 行）

**口述**：

> 「所以我只改检索，不动提示词。改两处：
> 第一，参数名精确匹配加权——问题里如果出现 cutoff_len 这种参数名，
> 而某个块的表格行首正好是它，给这个块额外加 8 分。
> 因为 v0 的问题就是参数散落在多张表里，BM25 只命中其中一张。
> 第二，top-k 从 3 提到 6——给模型的资料从 3 段增到 6 段。」

**关键：写预期（老师硬要求）**

**操作**：打开 `out/prediction.md`

> 「改之前我先写了预期：严格正确率从 56% 提到 68 到 72，
> 检索没命中从 92% 降到 60 到 70。这是改代码之前写的，不能事后改。」

## 第七段｜出结果（约 180 秒）

**操作**：
```bash
.venv/bin/python -c "
import csv
for split in ('optimize','test'):
    for v in ('v0','v1','v2'):
        try:
            rows=list(csv.DictReader(open('out/week1_'+split+'_'+v+'.csv',encoding='utf-8-sig')))
            rows=[r for r in rows if r['人工判分']]
            ok=sum(1 for r in rows if r['人工判分']=='对')
            print(split, v, str(ok)+'/'+str(len(rows)), str(round(ok/len(rows)*100))+'%')
        except FileNotFoundError:
            pass
"
```

**口述**：

> 「结果分两块看。
> 优化集：v0 56%，v1 80%，涨了 24 个点，配对检验 p=0.0036，显著。
> 测试集：v0 77%，v1 71%，v2 60%，反而一路降。」

> 「如果只看这个，结论是『改进没泛化』。但我又做了一步分析——」

**操作**：打开 `out/report.md` 第四节「关键发现：难度分层分析」

> 「按 v0 的表现把题分成难题和易题，拆开看：
> 难题上，v0 只有 8%，v1 到了 65%，涨了 57 个点。
> 易题上，v0 是 100%，v1 掉到 93%，降了 7 个点。
> 而且易题这个 7 个点，在两个集合上完全一样。」

> 「所以这个改动是『救极难题、伤易题』。
> 净效果取决于卷子里难题多还是容易题多——
> 优化集恰好难题多，所以涨；测试集恰好容易题多，所以降。」

> 「这不是过拟合，是这个改动本身的 trade-off。
> 下一周要做的，就是给它加个开关：题目简单时不用加权，题目困难时才用。」

**操作**：滚动到报告第七节「局限」

> 「最后是局限声明：样本只有 48 到 54 条，1 条题翻转就是 2 个百分点；
> 题目剔除标准是我定的；只在一个文档库上验证。这些我都写在报告里，没有藏。」
