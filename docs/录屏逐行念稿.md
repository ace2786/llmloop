## 第 5 步：诊断（1 分钟）

```bash
.venv/bin/python -c "
import csv
from collections import Counter
rows=list(csv.DictReader(open('out/week1_optimize_v0.csv',encoding='utf-8-sig')))
bad=[r for r in rows if r['人工判分'] in ('错','部分对')]
print('失败:',len(bad),'/',len(rows))
for k,v in Counter(r['失败原因'] for r in bad).most_common(): print(' ',k,v)
"
```

**念：**
> 「按失败原因归类。最大一类是『检索没命中』，占 92%。
> 编造内容 0 条，格式错 0 条。
> 而且两个模型正确率完全一样，56% 对 56%——说明瓶颈不在模型，在检索。」

**画面：** 打开 `out/prediction.md`

**念：**
> 「找到瓶颈之后，改代码之前我先写了预期：正确率提到 68-72%。
> 这是改之前写的，不能事后改。」

**画面：** 打开 `week1.py` 的 Retriever 类

**念：**
> 「改了两处：第一，参数名精确匹配加权——问题里出现 cutoff_len 这种参数名，
> 如果某段的表格行首正好是它，加 8 分。

## 第 7 步：出结果（★ 最重要，2 分钟）

```bash
.venv/bin/python -c "
import csv
for s in ('optimize','test'):
    for v in ('v0','v1','v2'):
        try:
            r=[x for x in csv.DictReader(open('out/week1_'+s+'_'+v+'.csv',encoding='utf-8-sig')) if x['人工判分']]
            ok=sum(1 for x in r if x['人工判分']=='对')
            print(s,v,str(ok)+'/'+str(len(r)),str(round(ok/len(r)*100))+'%')
        except FileNotFoundError: pass
"
```

**输出：**
```
optimize v0 30/54 56%
optimize v1 43/54 80%
test v0 37/48 77%
test v1 34/48 71%
test v2 29/48 60%
```

**念（慢一点，分三步）：**

**第一步：**
> 「优化集 56 到 80，涨了 24 个点，配对检验 p 等于 0.0036，显著。」

**第二步：**
> 「但测试集 77 到 71 再到 60，反而一路降。如果只看这个，结论是改进没有泛化。」

**第三步：**
> 「但我又拆开分析了一下——按 v0 的表现，把题分成难题和易题。」

**画面：** 打开 `out/report.md`，滚到「四、关键发现：难度分层分析」

**念：**
> 「难题从 8% 涨到 65%，涨了 57 个点；易题从 100% 掉到 93%，降了 7 个点。
> 所以这个改动是『救难题、伤易题』。
> 净效果取决于卷子里难题多还是容易题多——优化集恰好难题多，所以涨；
> 测试集恰好容易题多，所以降。」

**念（诚实说明）：**
> 「但易题这个下降，每个集合只有 2 条，在 30 条样本上属于噪声范围，
> 所以我只说是『观察到的方向』，不说是确定的机制。」
