## 一、这是个什么项目

一个「大模型应用自动调优平台」：给 RAG 类应用设定质量目标，平台自动循环
「评测 → 找失败原因 → 提修改 → 在没见过的题上重测」，变好保留、变差退回。

**你负责的部分：网页前端。**

---

## 二、★ 先看这一条，别踩雷

老师（指导教师）在任务书里的硬性要求，原文：

> **页面上的每个数字都必须由后端从真实数据实时算出，前端不能写死任何结果，
> 不能用 Mock 冒充真实功能，不能用预先录好的过程冒充实时运行。**

翻译成施工规则：

| 可以做 | 绝对不可以 |
|---|---|
| 后端接口没好时，**页面显示「功能未接入」并禁用按钮** | 先用假数据把页面填满，等后端好了再换 |
| 用 loading / 骨架屏表示等待 | 硬编码「85%」「120 道题」这类数字做演示 |
| 缺接口时提 issue 让后端补 | 自己在前端造一个「看起来像评测」的假流程 |

**判断标准很简单：把后端服务停掉，你的页面必须报错或者显示空状态，不能还显示一堆数字。**
这一条不通过，整个页面重做。

## 三、后端现状（哪些能联调，哪些还没有）

### ✅ A 区：已经写好并测过，可以直接联调

**基地址**：`http://127.0.0.1:8020`
**CORS**：已全开（`allow_origins=["*"]`），本地随便调
**鉴权**：除注册/登录外都要 `Authorization: Bearer <token>`

| 方法 | 路径 | 请求体 / 参数 | 返回 |
|---|---|---|---|
| POST | `/auth/register` | `{email, password}`（密码 ≥ 8 位） | `{user_id, token}` |
| POST | `/auth/login` | `{email, password}` | `{user_id, token}` |
| GET | `/auth/me` | — | `{id, email, created_at}` |
| POST | `/auth/logout` | — | `{ok: true}` |
| POST | `/apps` | `{name, base_url, model, description}` | 应用对象（含 `app_key`） |
| GET | `/apps` | — | 应用数组（每个带 `questions` 计数） |
| GET | `/apps/{app_id}` | — | 应用对象 + `questions` 计数 |
| DELETE | `/apps/{app_id}` | — | `{deleted: id}`（级联删题目） |
| POST | `/apps/{app_id}/questions/import` | `{items, raw_text, replace, seed}` | `{imported, seed, splits}` |
| GET | `/apps/{app_id}/questions` | `?split=&limit=50&offset=0` | `{total, splits, items[]}` |
| GET | `/apps/{app_id}/questions/stats` | — | `{optimize, valid, test, total}` |
| DELETE | `/apps/{app_id}/questions` | `?split=` | 更新后的计数 |

**关键数据结构**

```jsonc
// 应用对象
{
  "id": 1, "user_id": 1, "name": "LlamaFactory 文档助手",
  "app_key": "sk-xxxx",              // 给被测应用接入用
  "base_url": "http://...", "model": "qwen3-4b", "description": "...",
  "created_at": "2026-10-27 20:32:00",
  "questions": { "optimize": 6, "valid": 2, "test": 2, "total": 10 }
}

// 导入题目（items 支持两种写法）
{ "items": ["问题1", "问题2"] }
{ "items": [{"content": "问题1", "reference": "文档出处"}], "seed": 20261020 }

// 导入返回（切分比例固定 6:2:2，按 seed 洗牌）
{ "imported": 10, "seed": 20261020,
  "splits": {"optimize": 6, "valid": 2, "test": 2, "total": 10} }

// 题目列表
{ "total": 10, "splits": {...},
  "items": [{"id": 1, "app_id": 1, "split": "optimize",
             "content": "...", "reference": "...", "created_at": "..."}] }
```

**错误码**：`400` 参数错 / `401` 未登录或 token 失效 / `404` 应用不存在或不属于你 / `409` 邮箱已注册

**实测状态**：这 12 个接口已跑过 25 项自动化测试（含越权、级联删除、token 失效），全部通过。
接口本身可以信任，不用再验。

### ⛔ B 区：后端还没做，前端先别碰

| 功能 | 缺什么 | 谁做 |
|---|---|---|
| **发起一次评测** | 没有 `/apps/{id}/evaluate` 接口 | **后端**（还没排期） |
| 看评测结果（逐题对错） | 没有 runs 表和查询接口 | 后端 |
| 优化循环（诊断/提议/保留退回） | 整个 F1 引擎还没接进来 | 后端（阶段 2） |
| 回答检查（标红幻觉片段） | F3 模型还没接成服务 | 后端（阶段 2） |
| 版本对比 / 审批 | 依赖评测结果 | 阶段 2 |

**所以：先做 A 区能支撑的页面。B 区的东西，按钮可以放，但必须置灰并写「功能未接入」。**

## 四、你要做的页面（按优先级）

### 第一优先级（第 3 周检查点要求，11/10 前）

## 五、技术约束
