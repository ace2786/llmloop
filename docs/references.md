## 二、最值得对标的三个项目

### ① AutoRAG（最接近本项目目标）

```
https://github.com/Marker-Inc-Korea/AutoRAG
```

> AutoRAG: An Open-Source Framework for RAG Evaluation & Optimization with AutoML-Style Automation

**做法**：准备文档 → 自动试几十上百种 RAG 配置（分块、检索器、LLM 调用方式）→ 输出最优方案。

**与我们的区别**：

| | AutoRAG | 本项目 |
|---|---|---|
| 优化方式 | **穷举**（试几十种组合） | **诊断**（找瓶颈再改一处） |
| 判分 | 自动指标 | **人工判分**（老师硬要求） |
| 规模 | 大 | 小（54 条） |

**为什么不能穷举**：每试一种配置就要人工判 60 条，成本不可接受。
**「先诊断、再改一处」是被人工判分约束逼出来的方法，不是技术落后。**

**可借鉴**：目录结构、评测模块与优化模块的分离方式、检索层与生成层指标的划分。

### ② AWS IDP AutoOpt（闭环流程几乎一致）

```
https://cloud.tencent.com/developer/article/2721289
```

**流程**：评分 → 逐字段诊断错误 → 改配置 → 重评

**与本项目**：判分 → 诊断失败原因 → 改检索 → 重测

**可借鉴**：「逐字段诊断」比我们按四类失败原因分类更细。

### ③ 企业级 RAG 自动化评测平台（工程落地视角）

```
https://blog.csdn.net/2402_87628679/article/details/162973197
```

**内容**：核心指标解读、测试集构建、RAGAS 代码、私有化评测、可视化报表、定时巡检。

**可借鉴**：评测平台该有哪些模块（我们目前只有脚本）。

## 四、医疗领域参考（方法论可直接借）

### ① 医疗 RAG 40 组实验拆解

```
https://blog.csdn.net/m0_59164520/article/details/163086802
```

**核心结论**：
- 稠密检索优于混合检索（BM25 + 稠密）——在结构化医学教材语料上
- 查询改写 + 交叉编码器重排贡献了 90% 的准确率增益
- 领域模型优于通用模型

**可借鉴**：**对照组设计**。它用 40 组实验隔离变量，我们只有 3 组（v0/v1/v2）。
第 2 周可设计「只改 top-k / 只改加权 / 两者都改」三个对照组。

### ② NVIDIA 用 Ragas 评测医疗 RAG

```
https://developer.nvidia.com/zh-cn/blog/evaluating-medical-rag-with-nvidia-ai-endpoints-and-ragas/
```

**流程**：准备「问题 + 标准答案 + 检索上下文 + 模型回答」→ 算忠实度、答案相关性、上下文精度、上下文召回。

**可借鉴**：把「检索质量」与「回答质量」分开评。
本项目现在混在一起判（对/错），虽然用「失败原因」区分了，但可以更明确。

## 五、评测工具（了解即可，与本项目约束冲突）

| 工具 | 干什么 | 与本项目的关系 |
|---|---|---|
| **RAGAS** | RAG 评测，9 个指标（忠实度/相关性/上下文精度/召回等） | ⚠️ 依赖 LLM 判分，与「禁止 AI 判分」冲突 |
| **DeepEval** | 大模型应用测试框架（RAG/Agent/对话） | ⚠️ 同上 |
| **TruLens** | 评测 + 追踪 | ⚠️ 同上 |

**这些工具的核心都是「用 LLM 当裁判」。本项目走人工判分路线，因此不能直接采用，但它们的指标定义可以借鉴。**

## 六、三条技术路线的定位

| 路线 | 代表 | 判分方式 | 适合场景 |
|---|---|---|---|
| 穷举式自动优化 | AutoRAG | 自动指标 | 大量标注、追求极致效果 |
| 闭环 agent 自优化 | AWS IDP AutoOpt | LLM 自评 | 工程落地、成本敏感 |
| **人工小样本诊断** | **本项目** | **人工判分** | 毕设、要求可解释、禁止 AI 判分 |

**三条路都成立，区别在约束条件。本项目选择第三条，原因是被「判分必须人工」这条硬约束决定的。**

## 七、第 2 周可以做的三件事（由参考材料直接引出）

1. **设计对照组**（借鉴医疗那篇）
   - A 组：只改 top-k
   - B 组：只改参数名加权
   - C 组：两者都改
   - 隔离变量，看清各自贡献

2. **拆分评测维度**（借鉴 RAGAS / NVIDIA）
   - 检索层：检到的段落里有没有答案（Context Recall）
   - 生成层：回答是否有依据（Faithfulness）
   - 分开统计，能说清「是没检到，还是检到了答错」

3. **看 tinyBenchmarks**（老师指定）
   - 弄清「54 条样本的结论可信到什么程度」
   - 为样本量问题提供理论依据
