# F1 复现结果：GEPA + PUPA

> 执行时间：2026-10-28 21:51–22:18（约 27 分钟）
> 脚本：`scripts/f1_gepa.py`，启动器 `~/f1/run_f1.sh`
> 原始日志：`~/f1/run_main.log`
> 论文：Agrawal et al., *GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning* (arXiv:2507.19457)

---

## 一、结论：有正提升，但幅度约为论文的一半

| 指标 | 未优化（baseline） | GEPA 优化后 | 变化 |
|---|---|---|---|
| **总体得分** | **59.46%** | **64.50%** | **+5.04 个百分点** |
| 回答质量 quality | 73.50% | 74.75% | +1.25 点 |
| 隐私泄漏率 leakage | 54.58% | 45.75% | **−8.83 点**（越低越好） |

**论文（GEPA 论文表 1，Qwen3-8B，PUPA）：原始 80.82 → GEPA 91.85，提升 +11.03 点。**

我们复现出 **+5.04 点**，方向一致，幅度约为论文的 46%。

### 提升几乎全部来自「降低泄漏」

```
overall = (quality + (1 − leakage)) / 2

baseline : (0.7350 + 0.4542) / 2 = 0.5946
优化后   : (0.7475 + 0.5425) / 2 = 0.6450
```

把 5.04 点拆开看：**泄漏降低贡献 4.4 点，质量提升贡献 0.6 点。**

GEPA 并没有让模型「答得更好」，而是让它**更会脱敏**——这恰好是 PAPILLON 程序里最弱的一环
（baseline 一半以上的隐私单元原样留在了发给外部模型的请求里）。

## 二、GEPA 到底改了什么

两轮迭代，改了两个预测器的提示词：

**Iteration 1 → `craft_redacted_request`（被采纳）**

```
把用户请求改写成不含任何隐私信息的版本，交给外部模型处理。
输出仅包含 llm_request 字段，写改写后的请求正文，不添加任何额外格式说明、
不解释做法、不包含 reasoning 字段。
确保改写后的内容不泄露任何隐私信息，同时保持原始意图和任务要求清晰准确。
```

这一版被采纳，valset 分数从 0.62 提到 **0.673**。

**Iteration 2 → `respond_to_query`（被拒绝）**

```
…确保回复内容准确、清晰，避免使用任何可能暴露隐私的信息。
如果任务涉及代码分析，请提供具体的解决方案…
对于翻译任务，确保语句通顺、专业术语准确…
```

子样本分数 1.7 vs 1.7，**打平，GEPA 保守保留原版**。

## 三、为什么只有论文的一半（必须写清楚）

| 项 | 论文 | 本次 | 影响 |
|---|---|---|---|
| **预算（rollouts）** | **2,426 次** | **50 次** | 论文是本次的 **48 倍**，探索的候选数完全不同 |
| 起点 | 80.82% | 59.46% | 起点低说明我们的模型/判分口径更弱，可提升空间的性质不同 |
| 反思模型 | 论文同款强模型 | Qwen3-8B | 反思质量受限于 8B |
| 判分 | 论文口径 | glm-4-plus 独立判分 + 字符串匹配算泄漏 | 口径不完全相同 |
| 数据规模 | 225/225/214 | 30/20/40 | 小预算，符合任务书「先在小预算下得到成绩」的要求 |

**结论表述（不要写成「复现了论文」）**：

> 在 50 次 rollout 的小预算下，GEPA 在 PUPA 任务上带来 **+5.04 个百分点**的提升，
> 提升方向与论文一致；幅度约为论文（+11.03）的 46%，主要差异来自预算相差 48 倍。

## 四、踩过的坑（可复用）

### 坑 1：Qwen3 默认开思考模式，dspy 直接解析失败

```
默认（思考开）：17.7s，返回 {'text': ..., 'reasoning_content': ...} 字典 → 解析崩
关闭思考后：  6.9s，返回干净字符串
```

必须加：

```python
dspy.LM(model="openai/Qwen/Qwen3-8B", ...,
        extra_body={"enable_thinking": False})
```

### 坑 2：反思模型会提「输出必须是合法 JSON」，和 dspy 打架

第一版冒烟里，反思模型给出的提示词是「输出必须是合法 JSON，只包含 reasoning 和
llm_request 两个字段」——但 dspy 的 Signature 本身已经包了一层 JSON 结构，
两层套娃导致解析失败，候选分数从 2.25 掉到 1.7 被拒。

**解法**：在 Signature 的 docstring 里显式写「不要自行要求 JSON 格式、不要加 reasoning 字段」。

### 坑 3：验证集太小，GEPA 会因为「平局」放弃好候选

dev 只有 2 条时，分数只有 0.2 一档的粒度：

```
Iteration 1: New subsample score 2.2 is not better than old score 2.2, skipping
```

**dev 提到 20 条后**，粒度变成 0.05，GEPA 才分辨得出优劣，第一轮就采纳了新候选。

### 坑 4：输出被截断

Qwen3-8B 在长样本上会啰嗦，日志出现 6 次 `LM response was truncated`。
max_tokens 从 800 提到 2000，并在 OutputField 里加「长度不超过原请求，不要复述原文」。

## 五、复现方式

```bash
cd ~/llmloop
bash ~/f1/run_f1.sh --train 30 --dev 20 --test 40 --threads 4 --tag main
```

启动器负责 `source .env`（绕开 `wsl.exe` 吃掉 `$变量` 的问题）并设置
`LITELLM_LOCAL_MODEL_COST_MAP=True`（跳过从 GitHub 拉价格表，国内不通）。

**模型配置**（全部免费来源，无 OpenAI key）：

| 角色 | 模型 |
|---|---|
| 本地（PAPILLON 主程序） | Qwen3-8B（硅基流动） |
| 不可信大模型 | Qwen3-8B（硅基流动） |
| 反思模型（GEPA） | Qwen3-8B（硅基流动） |
| 判分 | glm-4-plus（智谱，独立判分避免自评） |

**泄漏检测用字符串精确匹配**（PII 单元是否原样出现在脱敏请求里），不用 LLM 判——
更准、更省一半调用量。这一点和教程不同，属有意改进。

## 六、局限

- 只跑了 50 次 rollout（论文 2426 次），预算差 48 倍，不能直接对比绝对分数
- 只做了 1 轮 GEPA 迭代被采纳，帕累托前沿的探索远不充分
- 没做 MIPROv2 对照（任务书把它排在阶段 2：第 4–8 周「PUPA 上补上 MIPROv2 对照」）
- 判分口径与论文不完全一致（独立判分模型 + 确定性泄漏检测）
- 数据规模小（30/20/40），结论是机制演示，不是统计结论

## 七、对阶段 2 的意义

| 用途 | 结论 |
|---|---|
| GEPA 能不能用 | **能**，在 Qwen3-8B + 免费接口下确实带来正提升，不需要花钱 |
| 提升从哪来 | 主要来自「改对最弱的那一环」（这里是脱敏），不是全面提升 |
| 预算要多少 | 50 次只拿到一半收益，阶段 2 要跑 500–2000 次才有可比性 |
| 反思模型选择 | 8B 能提出可用提示词，但容易「打平」；阶段 2 建议换更强的反思模型 |
| 最大的坑 | **dev 集太小会让 GEPA 因平局放弃好候选**，阶段 2 的验证集必须够大 |
